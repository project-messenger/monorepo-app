# 0004. Feature-Sliced Design на фронтенде

- **Статус:** принято
- **Дата:** 2026-11-14 (решение действует с настройки `apps/web`, записано задним числом)
- **Область:** web
- **Подготовил:** ИИ-агент (Claude Code) по запросу foxprogs
- **Задача:** [KAN-15](https://project-group-11.atlassian.net/browse/KAN-15)

## Контекст

ТЗ задаёт для фронтенда методологию Feature-Sliced Design и требует линтер, который проверяет её правила. Пять
фронтендеров разного уровня и агенты пишут код параллельно, так что правило «куда класть код» должно проверяться
автоматически, а не на ревью.

## Варианты

Сама методология задана ТЗ. Выбирали, как совместить её с Next.js App Router, у которого свои папки `app/` и
`pages/`:

1. **Слои FSD внутри `app/`.** Роутинг Next и слои смешиваются.
2. **Отдельный `src/` со слоями `_app`, `_pages`**, а `app/` в корне — только роутинг, по
   [гайду FSD для Next.js](https://feature-sliced.design/docs/guides/tech/with-nextjs).

## Решение

Вариант 2: слои `_app`, `_pages`, `widgets`, `features`, `entities`, `shared`; `app/` только реэкспортирует
страницы. Правила проверяет [steiger](https://github.com/feature-sliced/steiger) в `pnpm lint`. Подробно —
[`apps/web/docs/architecture.md`](../../apps/web/docs/architecture.md).

## Последствия

- Нарушения слоёв ломают `lint` и CI — агент получает понятную ошибку.
- Порог входа для джунов выше; помогает таблица «куда положить код» в документации.
