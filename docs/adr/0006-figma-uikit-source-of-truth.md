# 0006. Источник правды для UI-кита — макет Figma

- **Статус:** принято
- **Дата:** 2026-11-15
- **Область:** web
- **Подготовил:** ИИ-агент (opencode) по запросу пользователя
- **Задача:** [KAN-17](https://project-group-11.atlassian.net/browse/KAN-17)

## Контекст

Раньше правила `apps/web/AGENTS.md` считали источником правды код (текущий shadcn, preset `base-nova`), а Figma
подстраивалась под него. Файл Figma `6FEyS7TIMuiYKTY6HMIBDr` был старым community-китом shadcn и не использовался как
референс. Теперь у команды есть собственная дизайн-система: файл `9bp5uwYGyaGIRCt1ycuqz3` (страница `2004:2`,
19 экранов, только Light) с 64 цветовыми токенами, типографикой на Inter, шкалой размеров и 13 семействами
компонентов. Базовые элементы в `shared/ui` должны ей соответствовать и быть готовы к переиспользованию. Верстать
макет целиком или по страницам в рамках задачи запрещено.

## Варианты

1. **Оставить код источником правды** (shadcn по умолчанию), подгонять Figma под код. Не соответствует требованию
   «базовые элементы соответствуют дизайну»: дизайнер владеет макетом, а не кодом.
2. **Источник правды — макет Figma**, код подгоняется через токены и варианты `cva`. Страницы подхватывают новые
   стили автоматически. Минус: правила приходится обновить, а данные из Figma снимать через MCP с лимитом вызовов.

## Решение

Вариант 2. Источник правды — макет `9bp5uwYGyaGIRCt1ycuqz3`. Подход к реализации:

- Цвета: все токены макета переносятся в CSS-переменные `globals.css` (`:root`, `.dark`) и в `@theme inline`. Основные
  имена совпадают с shadcn, остальные получают префиксы (`--sidebar-*`, `--status-*`, `--input-*`, `--surface-*`).
- Типографика: роли макета задаются токенами `--text-<роль>` в `@theme inline`, Tailwind v4 генерирует из них короткие
  утилиты (`text-heading-page`, `text-body`). Отдельный React-компонент `Typography` не создаётся.
- Компоненты: недостающие, которые есть в shadcn (`select`, `alert`), добавляются через `shadcn add`. Компоненты без
  аналога в shadcn (`search`, `task-card`, `metric-card`, `navigation-item`, `workspace-switcher`, `status-select`)
  собираются вручную по образцу существующих (`cva`, `cn`, токены, без бизнес-логики) в `shared/ui`. Это осознанное
  исключение из правила «не писать `shared/ui` с нуля».
- Тёмной темы в макете нет: значения `.dark` выводятся из новой светлой палитры. Если читаемо не получится, тема
  отключается отдельным решением.
- Логотип (`shared/ui/logo.tsx`) в задачу не входит. Base UI примитивы и логика доступности не меняются.

## Последствия

- Раздел Design system в `apps/web/AGENTS.md` переписан: старый файл Figma удалён из правил, источник правды — новый макет.
- Значения из Figma снимаются через MCP; из-за лимита Starter-плана данные фиксировались в
  `docs/backlog/ui-kit-figma/figma-data.md` (итог перенесён в [ADR-0007](./0007-figma-uikit-implementation.md)).
- Нет данных макета по hover, focus, pressed, disabled: эти состояния сохраняются из shadcn и перекрашиваются токенами.
- Внешний вид существующих страниц (`landing`, `login`, `register`) изменится вместе с токенами; в PR нужны скриншоты.
- Работа разбита на подзадачи в `docs/backlog/ui-kit-figma/` (каталог удалён после закрытия, итог — [ADR-0007](./0007-figma-uikit-implementation.md)).
