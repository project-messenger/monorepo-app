# 0005. `AGENTS.md` — единый источник правил для агентов

- **Статус:** принято
- **Дата:** 2026-11-14
- **Область:** весь проект
- **Подготовил:** ИИ-агент (Claude Code) по запросу foxprogs
- **Задача:** [KAN-15](https://project-group-11.atlassian.net/browse/KAN-15)

## Контекст

ТЗ требует использовать ИИ на максимум — в разработке, ревью, тестах, через скилы и агентов, — но с оговоркой:
«пытаться всё сделать с одного-двух промптов даже не стоит», качество кода и зоны ответственности важнее, коммиты
на 10 тысяч строк — «путь в никуда». Агентам нужны одинаковые правила, а не надежда на удачный промпт.

В команде пользуются Claude Code, Cursor, opencode и Codex / ChatGPT; у каждого свой файл инструкций. Раньше правила лежали только в `apps/web/AGENTS.md`: бэкенд и запуски из корня
оставались без правил, а Claude Code `AGENTS.md` сам не читал.

## Варианты

1. **Файл под каждый инструмент** (`CLAUDE.md`, `.cursor/rules`, …) со своими правилами. Правила разойдутся.
2. **Один `AGENTS.md` на всю монорепу.** Длинный, агент фронтенда читает правила бэкенда и наоборот.
3. **Иерархия `AGENTS.md`:** корень — общие правила, пакет — только дополнения. Для Claude Code — однострочные
   `CLAUDE.md` с `@AGENTS.md` на каждом уровне.

## Решение

Вариант 3. Устройство и правила изменения — [`docs/ai-agents.md`](../ai-agents.md). Общие для всей монорепы
документы (git, архитектура, ADR) переехали из `apps/web/docs` в корневой `docs/`.

## Последствия

- Любой инструмент получает одинаковые правила; новый инструмент — однострочный адаптер.
- Правило нельзя дублировать между уровнями — за этим следим на ревью.
- Требования ТЗ к качеству (маленькие PR, тесты, проверки перед «готово») записаны в `AGENTS.md` как правила для агента.
- `experimental.agentFeedback` в Next.js выключен: он просил агентов отправлять отзывы в Vercel.
