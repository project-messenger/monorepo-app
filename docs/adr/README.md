# Архитектурные решения (ADR)

[← к документации](../README.md)

ADR (Architecture Decision Record) — короткая запись одного решения: какой был вопрос, какие варианты
рассматривали, что выбрали и чем за это платим. Зачем — [ADR-0001](./0001-record-architecture-decisions.md).

Все ADR проекта лежат **здесь, в одной папке**, с общей нумерацией — и для фронтенда, и для бэкенда. Часть проекта,
к которой относится решение, указывается в поле «Область».

## Когда писать ADR

Пишите, если решение:

- затрагивает больше одной задачи или больше одной части монорепы;
- трудно или дорого отменить (база данных, формат контракта, авторизация, структура проекта);
- кто-то через месяц спросит «а почему так?».

Не нужен ADR для того, что уже однозначно задано правилами (`AGENTS.md`, `docs/`), и для мелочей внутри одной задачи.

## Как принимаем

Отдельного круга согласования нет: **ADR принимается вместе с PR**. Approve ревьюера и merge означают, что решение
принято. Поэтому в `main` у ADR статус только «принято» или «заменено».

- **Решение появилось по ходу задачи** (столкнулись с проблемой, обсудили в чате, договорились) — ADR кладётся в тот
  же PR, что и код. Что обсуждали и какие были доводы — в разделах «Контекст» и «Варианты»: ссылок на чат нет,
  поэтому ADR должен быть понятен без него.
- **Решение нужно другим до начала их работы** (контракт API, авторизация, схема БД) — сначала договоритесь в чате
  команды, потом ADR идёт в первый PR, который это решение реализует. Если код будет нескоро, а решение уже ждут —
  можно открыть PR только с ADR.
- **Ревьюер PR проверяет и ADR**: согласен ли он с решением, а не только с кодом. Не согласен — обсуждение в PR.

Себе approve поставить нельзя: GitHub не даёт автору одобрить свой PR. Поэтому решение всегда видит ещё хотя бы один
человек.

## Как писать

1. Скопируйте [`template.md`](./template.md) в `NNNN-короткое-название.md` (следующий номер, слова через дефис, по-английски).
2. Заполните и добавьте строку в таблицу выше — в том же PR.
3. В описании PR отметьте, что в нём есть ADR, чтобы ревьюер его не пропустил.

Принятый ADR не переписываем. Решение поменялось — новый ADR, а у старого статус «заменено [NNNN](…)».

ADR может подготовить ИИ-агент, но решение принимают люди. В ADR, который готовил агент, это указано в поле
«Подготовил».
