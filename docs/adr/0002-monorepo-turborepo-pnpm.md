# 0002. Монорепа на Turborepo + pnpm workspaces

- **Статус:** принято
- **Дата:** 2026-11-14 (решение действует с создания репозитория, записано задним числом)
- **Область:** весь проект
- **Подготовил:** ИИ-агент (Claude Code) по запросу foxprogs
- **Задача:** [KAN-15](https://project-group-11.atlassian.net/browse/KAN-15)

## Контекст

ТЗ задаёт pnpm и TypeScript и для фронтенда, и для бэкенда. Обе стороны делят контракт: схемы, типы, события
WebSocket. Команде нужно видеть изменения обеих сторон в одном PR, а ревьюер должен понимать, что изменение API не
сломало фронтенд.

## Варианты

1. **Два репозитория** + опубликованный пакет с типами. Изменение контракта — три PR и публикация версии.
2. **Монорепа на pnpm workspaces + Turborepo.** Общий пакет подключается ссылкой, задачи запускаются и кэшируются по
   всем пакетам одной командой.
3. **Монорепа на Nx.** Мощнее, но тяжелее в освоении для учебного проекта.

## Решение

Вариант 2: `apps/web`, `apps/api`, `packages/shared` (`@app/shared`), pnpm 9, Turborepo. Пакеты ставятся только
через pnpm из корня.

## Последствия

- Изменение контракта и обеих сторон — один PR.
- Один CI на всё: проверки всех пакетов запускаются одной командой Turborepo.
- Все команды запускаются из корня (`pnpm --filter <пакет> …`); `npm install` внутри пакета ломает монорепу.
