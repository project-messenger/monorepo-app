# 0010. PostgreSQL и Redis для локальной разработки через Docker Compose

- **Статус:** принято
- **Дата:** 2026-11-20
- **Область:** весь проект
- **Подготовил:** ИИ-агент (Codex) по запросу пользователя; параметры согласованы пользователем
- **Задача:** [KAN-34](https://project-group-11.atlassian.net/browse/KAN-34), реализация Compose — KAN-35

## Контекст

Разработчикам нужен одинаковый способ запуска PostgreSQL и Redis одной командой из корня. API и фронтенд
продолжают работать через pnpm на компьютере разработчика. Настройка загрузки корневого `.env` в API — KAN-36,
проверка первого запуска другим участником — KAN-37.

## Варианты

1. **Установка сервисов на каждый компьютер вручную.** Различия версий и настройки усложняют первый запуск.
2. **Docker Compose только для инфраструктуры.** Одинаковые образы и команды, существующий запуск приложений.
3. **Контейнеризация всех приложений сразу.** Требует дополнительной настройки сборки и watch-режима.

## Решение

Вариант 2. В корне — `docker-compose.yml`, команды `infra:up`, `infra:down`, `infra:status`, `infra:logs`.
`infra:up` ждёт успешных healthcheck обоих сервисов; ошибки не подавляются.

Официальные образы: `postgres:18.7-bookworm` и `redis:8.10.3-trixie`. Пользователь выбрал PostgreSQL 18.7 после
проверки: официальный образ согласованной ранее 19.0 ещё не опубликован. Версии фиксируются в Compose.
Порты публикуются только на `127.0.0.1`; внешние порты и параметры PostgreSQL задаются через корневой `.env`.
Пользователь `messenger`, пароль `messenger_local` — открытые локальные примеры.

Данные обоих сервисов — в именованных volumes. Redis использует AOF, `appendfsync everysec`, без периодических
RDB-снимков, чтобы локальное состояние переживало остановку и пересоздание контейнера.

## Последствия

- Нужен запущенный Docker с Compose, поддерживающим `up --wait --wait-timeout`.
- Обычный `infra:down` сохраняет данные. `docker compose down --volumes` явно удаляет все локальные данные.
- При аварии Redis может потерять примерно последнюю секунду записей.
- Параметры PostgreSQL применяются при создании пустой базы; изменение `.env` не меняет существующие учётные данные.
- Подключение ORM, Redis-клиента, удалённые окружения и production выполняются отдельно.
