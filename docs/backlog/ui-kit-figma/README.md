# KAN-17: UI-кит по дизайн-системе из Figma

[← к бэклогу](../README.md) · Jira: [KAN-17](https://project-group-11.atlassian.net/browse/KAN-17) · Ветка: `KAN-17/align-ui-kit-with-figma`

Этот файл — индекс и **журнал прогресса**. Если работа остановилась, продолжать надо отсюда: найти первую подзадачу со статусом «не начата» или «в работе», открыть её файл и идти по чеклисту.

## Цель

Привести базовые элементы (`apps/web/src/shared/ui`), токены и типографику в соответствие с дизайн-системой в Figma. Страницы приложения подхватывают новые стили автоматически, потому что используют токены и компоненты `shared/ui`.

## Что запрещено в рамках KAN-17

- Верстать макет целиком, отдельные страницы или виджеты.
- Менять логотип (`shared/ui/logo.tsx`).
- Редактировать Base UI примитивы и их логику доступности (только стили и варианты).
- Добавлять пакеты и компоненты через `shadcn add` без подтверждения пользователя (список подтверждён ниже).

## Принятые решения (подтверждены пользователем)

1. Источник правды — новый макет Figma, код подгоняется под него. Оформляется ADR [0006](../../adr/0006-figma-uikit-source-of-truth.md), правится раздел Design system в `apps/web/AGENTS.md`.
2. Все 64 токена цвета переносятся в CSS-переменные (`:root`, `.dark`, `@theme inline`). Основные имена совпадают с shadcn, остальные получают префиксы (`--sidebar-*`, `--status-*`, `--input-*`, `--surface-*` и т.д.).
3. Типографика: в `@theme inline` задаются токены `--text-<роль>` вместе с `--leading`, `--font-weight`. Из них Tailwind v4 генерирует короткие утилиты (`text-heading-page`, `text-body`, `text-caption`). Одного класса достаточно для размера, высоты строки и веса. Стандартные `text-sm`, `text-lg` остаются рабочими. Отдельный React-компонент `Typography` не создаём.
4. Недостающие компоненты: `select` и `alert` добавляем через `shadcn add`, остальные (`search`, `task-card`, `metric-card`, `navigation-item`, `workspace-switcher`, `status-select`) собираем вручную по образцу существующих (`cva`, `cn`, токены, без бизнес-логики) в `shared/ui`.
5. Тёмной темы в макете нет: значения `.dark` выводим из новой светлой палитры. Если не получится сделать читаемо, `.dark` отключаем отдельным решением.
6. Шрифт: Inter (в макете), кириллица нужна. Geist Mono для моноширинного остаётся.

## Порядок и правила работы

1. Подзадачи идут по номерам, независимые (02, 03, 04) можно в любом порядке после 01.
2. После каждой подзадачи: `pnpm --filter web verify` зелёный, статус в таблице обновлён, чеклист в файле подзадачи отмечен.
3. Коммиты по формату `<type>: KAN-17 <описание>` (английский, без scope). Коммитим и пушим только по просьбе пользователя.
4. Значения из Figma, которых не хватает, не придумываем: помечаем в `figma-data.md` как «нужно уточнить» и дочитываем из макета, когда лимит MCP восстановится.
5. Новые пакеты и `shadcn add` только после подтверждения (подтверждены `select` и `alert`).
