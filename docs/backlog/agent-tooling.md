# Общие настройки и сценарии для ИИ-агентов

[← к бэклогу](./README.md) · Jira: —

## Зачем

Правила для агентов уже общие ([`AGENTS.md`](../../AGENTS.md), [docs/ai-agents.md](../ai-agents.md)), а повторяющиеся
действия каждый пока описывает агенту своими словами. Из-за этого результат у семи человек разный: кто-то забудет
ключ Jira в ветке, кто-то — шаблон PR. Готовые сценарии («скиллы», команды) делают эти шаги одинаковыми у всех.

## Кандидаты

- [ ] **Начать задачу** (`/start-task KAN-N`): прочитать задачу в Jira, создать ветку `KAN-N/<описание>` от свежего
      `main`, найти нужные `AGENTS.md` и гайды, предложить план.
- [ ] **Завести задачу в Jira** по описанию из чата или из файла [бэклога](./README.md): заголовок, ожидаемый
      результат, критерии готовности.
- [ ] **Подготовить PR**: прогнать проверки затронутых пакетов, написать коммит и заголовок по
      [workflow](../workflow.md), заполнить описание по шаблону — но открыть PR только после подтверждения человека.
- [ ] **Добавить эндпоинт** (после задачи [Контракт API](./api-contract.md)): DTO на Zod, контроллер, сервис, тесты,
      перегенерация `openapi.json` — по эталонному эндпоинту.
- [ ] Общие настройки в репозитории: `.claude/settings.json` (разрешения на частые безопасные команды, хуки) и
      `.mcp.json` (Figma, Jira/Confluence), чтобы не настраивать каждому вручную. Секреты и токены туда не кладём.

## Решения до начала

- [ ] Где хранить сценарии, чтобы их видели все инструменты команды (Claude Code, Cursor, opencode, Codex): у каждого
      свой формат (`.claude/skills/`, правила и команды Cursor и т. д.). Проверить по документации каждого, какие
      поддерживают общий формат Agent Skills, и выбрать одно место — как с `AGENTS.md`
      ([ADR-0005](../adr/0005-agents-md-single-source.md)).
- [ ] Доступ агентов к Jira: через MCP-сервер Atlassian или вручную (агент пишет текст, человек заводит задачу).
      Отправка данных во внешний сервис — только с согласия команды (правило из `AGENTS.md`).
