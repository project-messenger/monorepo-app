# Лимиты ревью CodeRabbit

[← к бэклогу](./README.md) · Jira: —

## Зачем

CodeRabbit работает на бесплатном плане для open source: репозиторий публичный, звёзд нет. На этом плане лимит — от 1
до 10 ревью PR в час **на одного разработчика** (скользящее окно), чем больше звёзд, тем больше
([документация](https://docs.coderabbit.ai/management/rate-limits)). В PR #27 первый пуш получил ревью, а пуш с
исправлениями через ~10 минут — «Review limit reached». Ревью при этом пропускается, а не ставится в очередь, и
проверка CodeRabbit в PR всё равно зелёная: легко не заметить, что ревью не было.

Ревью тратят:

- каждый пуш в открытый PR (инкрементальное ревью);
- открытие PR и перевод из draft в «готов»;
- кнопка Update branch в GitHub — это тоже пуш;
- команда `@coderabbitai review` в комментарии.

## Что можно сделать без изменения настроек

- Исправления по ревью собирать и пушить **одним пушем**.
- Пока PR в работе — держать его draft (`drafts: false` уже стоит, черновики не ревьюятся), отметить готовым один раз.
- Сколько осталось — комментарий `@coderabbitai rate limit` в PR.
- Ревью пропущено — после окна запросить `@coderabbitai review`.

## Что сделать (нужно решение команды)

- [ ] `.coderabbit.yaml`: `reviews.auto_review.auto_incremental_review: false` (по умолчанию `true`). Тогда CodeRabbit
      ревьюит PR при открытии, а следующие пуши — только по `@coderabbitai review`. Минус: ревью исправлений надо
      запрашивать руками.
- [ ] Или оставить инкрементальное ревью, но уменьшить `reviews.auto_review.auto_pause_after_reviewed_commits` (по
      умолчанию 5): после стольких проверенных коммитов автоматическое ревью встаёт на паузу.
- [ ] Записать выбранный порядок в [`docs/workflow.md`](../workflow.md) (раздел про PR и ревью).

Что не помогает: `path_filters` уменьшают число файлов в одном ревью, но не число ревью. Сгенерированный клиент Orval и
`pnpm-lock.yaml` CodeRabbit и так пропускает. Снять лимит можно только платным планом или оплатой по использованию —
это решение не для этой задачи.
