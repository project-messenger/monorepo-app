## Зачем

Способ входа выбран: email и пароль, серверная сессия в `httpOnly`-cookie —
[ADR-0013](../adr/0013-auth-server-session.md). Здесь — что осталось сделать вне задачи бэкенда.

## Фронтенд

- [ ] Страниц входа и регистрации ещё нет: `features/auth` — заготовка из шаблона. В настоящей форме входа нет
      «Запомнить меня»: в контракте её нет, срок сессии один для всех.
- [ ] До первой формы — [клиент API](./api-client.md): клиент Orval должен ходить на бэкенд и видеть ответы 4xx.
      При запросах напрямую на `API_URL` — с `credentials: 'include'`, иначе браузер не отправит cookie сессии.
- [ ] `apps/web/src/shared/api/session.ts` проверяет ответ `GET /api/auth/me` через `UserSchema` из `@app/shared`, а
      HTTP-схемы должны жить в `apps/api` ([ADR-0009](../adr/0009-api-contract-openapi-orval.md)). `UserSchema` из
      `@app/shared` удалить, но сначала решить: тип `User` от Orval есть только при компиляции, клиент Orval тело ответа
      не проверяет. Значит, либо оставляем проверку во время выполнения (своя схема Zod на фронте или схемы Zod,
      которые умеет генерировать Orval), либо отказываемся от неё — тогда меняется тест «падает, если ответ не совпадает
      с UserSchema» в `shared/api/session.test.ts`. Затронет и `features/auth/model/schemas.test.ts`.

## WebSocket

- [ ] Когда подключим socket.io: пользователь определяется по той же cookie при подключении.
- [ ] Выход из канала или удаление из него — сервер выводит соединения пользователя из комнаты этого канала (не
      отключает: остальные каналы продолжают работать).
- [ ] Выход из аккаунта (logout) или удаление сессии — сервер отключает сокеты этой сессии, иначе завершённая сессия
      будет получать сообщения до переподключения.
