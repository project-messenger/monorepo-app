# Team Messenger Monorepo

Современный корпоративный мессенджер с поддержкой Kanban-задач, интеграцией с GitHub и AI-ассистентом.

Стек: **Turborepo + pnpm**, **Next.js**, **NestJS**, **PostgreSQL + Redis**, **Prisma**, **Zod** и **Orval**.

## Порты приложений

Для корректной совместной работы сервисы распределены по портам:

- **Фронтенд (Next.js - `apps/web`):** `http://localhost:3000`
- **Бэкенд (NestJS API - `apps/api`):** `http://localhost:3001`

## Предварительные требования

У вас на компьютере должны быть установлены:

- **Node.js** (версия 20+ рекомендуется)
- **pnpm** (версия 9+)

Редактор — VS Code или Cursor: при открытии проекта они предложат рекомендуемые расширения
(`.vscode/extensions.json`), а общие настройки (форматирование Prettier при сохранении, ESLint, Tailwind) подхватятся
из `.vscode/settings.json`. Личные настройки держите в пользовательских настройках редактора, а не в этих файлах.

## Настройка окружения (.env)

1. Скопируйте файл-шаблон в рабочий `.env` в корне проекта:

```bash
   cp .env.example .env
```

2. Откройте `.env` и при необходимости настройте параметры (например, строку подключения к базе данных или секретные ключи). _Обратите внимание: телеметрия Turborepo в шаблоне уже отключена._

## Быстрый старт (Разработка)

1. Клонируйте репозиторий и установите зависимости **из корня проекта**:

```bash
pnpm install

```

2. Запуск всего проекта в режиме разработки (параллельно поднимется и бэкенд на 3001, и фронтенд на 3000):

```bash
pnpm dev

```

### Полезные команды (шорткаты из корня):

- `pnpm dev:api` — запустить только NestJS бэкенд.
- `pnpm dev:web` — запустить только фронтенд.
- `pnpm build` — собрать весь проект для проверки.
- `pnpm typecheck` — проверить TypeScript во всем репозитории.
- `pnpm lint` — запустить линтер.
- `pnpm verify` — все проверки фронтенда: typecheck + lint + Prettier + тесты.
- `pnpm test:web` — unit- и компонентные тесты фронтенда (Vitest).
- `pnpm test:web:e2e` — e2e-тесты фронтенда (Playwright).
- `pnpm format:web` — отформатировать код фронтенда (Prettier).

## Как работать с общим пакетом (`packages/shared`)

В папке `packages/shared` лежит то, что Swagger не описывает, а нужно обеим сторонам: события WebSocket (названия и Zod-схемы данных) и общие константы. HTTP-схемы сюда не кладём — фронтенд получает их от Orval.

- **Добавление нового события или схемы его данных:**

1. Создайте файл в `packages/shared/src/schemas/`.
2. Экспортируйте его в `packages/shared/src/index.ts`.
3. Пакеты `api` и `web` подхватят изменения автоматически.

Правила изменения пакета (в одном PR с обеими сторонами) — [packages/shared/AGENTS.md](./packages/shared/AGENTS.md).

## Как использовать Zod и Orval (Фронтенд + Бэкенд контракт)

HTTP-контракт описывает бэкенд (Zod-схемы DTO → OpenAPI), фронтенд генерирует из него клиент через Orval. Swagger на
бэкенде пока не подключён — направление и план в [docs/architecture.md](./docs/architecture.md#контракт-фронтенд--бэкенд).

1. **На бэкенде (`apps/api`):**

- Вы описываете эндпоинты в NestJS с помощью `@nestjs/swagger`.
- При запущенном бэкенде схема доступна по адресу `http://localhost:3001/api-json`.

2. **На фронтенде (`apps/web`):**

- Когда бэкендеры добавляют новые эндпоинты, фронтендер может автоматически сгенерировать готовые React Query хуки и типы одной командой (бэкенд должен быть запущен, подробнее — [`apps/web/docs/tooling.md`](apps/web/docs/tooling.md#orval--клиент-api-из-swagger)):

```bash
pnpm --filter web generate-api

```

- После этого в коде фронтенда можно использовать автогенерируемые хуки с полным автодополнением (например, `useGetMessages()`).
